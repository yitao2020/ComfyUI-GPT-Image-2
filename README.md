# ComfyUI GPT Image 2 插件

## 内置“立即生成”与跨批次并发

无需安装额外并发插件。点击节点内 **▶ 立即生成**，上一批运行时仍可继续提交；
每次自动新建独立的保存图像结果节点，图片返回后自动展示和保存，画布不自动跳转。
生成节点不显示详细日志，页面没有并发悬浮按钮。**全部记录**可查看任务详情。
两个图像插件单独安装或同时安装都支持。原生“运行”和单次多图并发保持原有行为。

**曾安装 ComfyUI-API-Immediate 的用户：请将旧独立插件移出 custom_nodes，再重启并 Ctrl+F5 刷新。**

完整说明、支持的上游节点和测试方式见 [内置并发使用说明](IMMEDIATE_GENERATION.md)。


基于 [apiyi.com](https://api.apiyi.com) 的 **GPT Image 2 / 2.5**（OpenAI 旗舰图像生成模型）的 ComfyUI 插件，支持 **2.0 与 2.5 模型下拉切换**，切换后参数下拉项会自动跟着变。

> **下图由本插件生成**：4K 画质，16 格篮球训练动作示意图，展示了 GPT Image 2 在多主体、复杂构图和中文文字渲染上的能力。

![GPT Image 2 生成示例 - 篮球训练动作示意图](assets/gpt-image2-example.jpg)

## 功能特性

| 特性 | 说明 |
|------|------|
| **2.0 / 2.5 模型切换** | 6 个模型 + 1 个别名下下拉，官方代理线与反向 -vip 线都覆盖 |
| **参数随模型动态收窄** | 切换模型后 `size` / `quality` 下拉项与 `background` 显隐自动更新 |
| **quality 档位对齐** | 2.5 多出 `xhigh` / `max`；跨版本乱选会自动按 token 量对齐，不会报 400 |
| **文生图** | 输入文本提示词生成图片 |
| **图片编辑** | 上传参考图 + 编辑指令生成新图片 |
| **多图融合** | 支持最多 5 张参考图同时输入 |
| **批量并发生成** | 一次最多生成 9 张，本地并发 N 个请求，输出为 batch |
| **Mask 局部重绘** | 支持透明蒙版局部重绘 |
| **精确尺寸控制** | 30 种官方预设尺寸（1K/2K/4K 各 10 种比例） |
| **透明背景** | 支持的模型可返回 alpha PNG |
| **中文友好** | 原生支持中文提示词 |
| **文字渲染** | high/max 档位下精细文字几乎不糊 |

## 模型下拉选项

| 下拉值 | 代际 | 通道 | 特点 |
|--------|------|------|------|
| `gpt-image-2` **(默认)** | 2.0 | 官方代理 | 上一代基线，支持 `auto` 与自定义尺寸 |
| `gpt-image-2-vip` | 2.0 | 反向通道 | 上一代基线，只认 30 种预设尺寸，拒绝 `xhigh`/`max` |
| `gpt-image-2.5-flare` | 2.5 | 官方代理 | 速度优先，22–138s，画面更柔和、细节更少 |
| `gpt-image-2.5-sunburst` | 2.5 | 官方代理 | 质量 / 编辑优先，37–120s，视觉最接近上一代 |
| `gpt-image-2.5-flare-vip` | 2.5 | 反向通道 | 速度优先版，**日常批量首选** |
| `gpt-image-2.5-sunburst-vip` | 2.5 | 反向通道 | 质量 / 编辑优先，日常文本生图默认 |
| `gpt-image-2.5-vip` | 2.5 | 反向通道 | `sunburst-vip` 的别名，两者等价 |

> 三者同价：$0.03 / 张，**1K / 2K / 4K 全部不加价**。

### 2.0 与 2.5 到底差在哪

按官方文档，**唯一的公开参数差异是 `quality` 的 `xhigh` / `max` 两档**。`size`、`background`、`mask`、`response_format` 在两代上是完全一致的。

| 对比项 | `gpt-image-2-vip`（2.0） | `gpt-image-2.5-*-vip`（2.5） |
|--------|--------------------------|------------------------------|
| quality 档位 | `auto` / `low` / `medium` / `high` | 再加 `xhigh` / `max` |
| 输出 token（2048×1152） | low 157 / medium 1413 / high 5650 | low 157 / medium 367 / high 1413 / xhigh 2511 / max 5650 |
| 串行延迟 | ~90–150s | flare 22–138s / sunburst 37–120s |
| 默认 size | `2048x2048`（flare-vip 为竖屏） | 同上 |
| size 支持 | 同样是那 30 种预设 | 同样是那 30 种预设 |

⚠️ **档位不是等价映射**：**2.5 的 `high` 只等于 2.0 的 `medium`**；**2.5 的 `max` 才等于 2.0 的 `high`**。要最高质量，2.5 发 `max`，2.0 发 `high`。

本插件在模型与 quality 不匹配时会**自动转换**并在 `info` 里写明，而不是让上游给你一个 400：

- 2.5 专用档 `xhigh`/`max` 选到 2.0 模型上 → 降级为 `high`
- 2.0 的 `high` 切到 2.5 → 对齐升级为 `max`（保持同等 token 量）


## 老工作流会自动迁移，不用手动改

本版本新增了 `model` 和 `background` 两个下拉框。ComfyUI 的 `widgets_values` 是**按位置**存的，
新增 widget 会让老存档的每个参数往后错一位（`seed` 会收到 `'randomize'`，直接报
`Failed to convert an input value to a INT value: seed, None`）。

插件在前端做了自动迁移，用你存档的**长度**判断版本，再按旧名字序列把值还原回去：

| 存档 widgets_values 长度 | 含义 | 处理 |
|---|---|---|
| 8 | `num_images` 之前保存的 | 按旧序列还原，`model` / `background` 取默认值 |
| 9 | `num_images` 之后保存的 | 同上，且 `num_images` 的值也会保留 |
| 11 | 新版本保存的 | 不动 |

所以老工作流打开后**行为和以前完全一致**（`model` 默认是 `gpt-image-2`），只是你可以顺手把它改成 2.5。
迁移日志会打印在浏览器控制台（`[GPT Image 2] 已把旧工作流的 N 个参数迁移到新布局`）。

> 如果前端 JS 因为缓存没生效，Python 侧还有第二道兜底：所有参数都会做类型/取值校验，
> 脏值退化成默认值并写进 `info` 日志，**不会让节点抛异常**（但参数值可能不是你想要的，这时请硬刷新）。

## 配置 API 密钥

首次使用时，在节点中输入您的 API 密钥（格式：`sk-xxxxxx`）。

> ⚠️ **密钥不会被自动写入磁盘**。节点只会在你输入时把密钥用于当次请求，不会保存。
>
> 如果你希望免重复输入，可以**手动**在节点目录下创建 `api_key.txt`，把密钥单独写进一行。
> 该文件已在 `.gitignore` 中，**不会被提交到仓库**，但仍建议你不要把它放在共享目录里。

## 节点参数说明

### 必填参数

| 参数 | 说明 |
|------|------|
| `api_key` | API 密钥（sk-xxxxxx格式） |
| `model` | 模型下拉，见上表（默认 `gpt-image-2`） |
| `prompt` | 提示词（建议把场景描述放在最前面） |
| `size` | 尺寸下拉，**选项会随模型变化**（默认 `1024x1024`） |
| `quality` | 画质下拉，2.5 多出 `xhigh` / `max` |
| `output_format` | `png` / `jpeg` / `webp` |
| `output_compression` | 压缩率 0–100（`png` 时忽略） |

### 尺寸选择（30 种官方预设）

> 表格里的尺寸**像素精确且不分档加价**。非预设尺寸不会报错，但会被上游改写（对齐到 16 的倍数，过小则抬升到最小边），所以想锁定精确像素就用下拉框里的值。

| 比例 | 1K Fast | 2K Recommended | 4K Detail |
|------|---------|----------------|-----------|
| 1:1 Square | `1280x1280` | `2048x2048` | `2880x2880` |
| 2:3 Portrait | `848x1280` | `1360x2048` | `2336x3520` |
| 3:2 Photo | `1280x848` | `2048x1360` | `3520x2336` |
| 3:4 Portrait | `960x1280` | `1536x2048` | `2480x3312` |
| 4:3 Standard | `1280x960` | `2048x1536` | `3312x2480` |
| 4:5 Social | `1024x1280` | `1632x2048` | `2560x3216` |
| 5:4 Large | `1280x1024` | `2048x1632` | `3216x2560` |
| 9:16 Story | `720x1280` | `1152x2048` | `2160x3840` |
| 16:9 Wide | `1280x720` | `2048x1152` | `3840x2160` |
| 21:9 Cinema | `1280x544` | `2048x864` | `3840x1632` |

另外保留了旧版本节点用过的 `auto`、`1024x1024`、`1536x1024`、`1024x1536`，用于兼容历史工作流
（`auto` 只对官方代理线有意义，反向 `-vip` 模型的下拉里不会出现）。

**选档建议**

- **1K Fast**：草稿、缩略图、A/B 测试
- **2K Recommended**：默认档，电商主图 / 海报 / 信息图
- **4K Detail**：打印、大屏、视频封面。⚠️ 4K 更容易触发上游 500，失败请先降到 2K

### 画质选择

| 画质 | 2.0 | 2.5 | 用途 |
|------|-----|-----|------|
| `low` | ✅ | ✅ | 草图 / 批量测试 |
| `medium` | ✅ | ✅ | 日常使用 |
| `high` | ✅ | ✅ | 精细纹理 |
| `xhigh` | ❌ | ✅ | 2.5 专属，≈2.0 的 high 的一半再多点 |
| `max` | ❌ | ✅ | 2.5 专属，**≈2.0 的 high 档 token 量** |
| `auto` | ✅ | ✅ | 模型自动判断 |

### 可选参数

| 参数 | 说明 |
|------|------|
| `input_image` | 输入图像，用于编辑或多图融合 |
| `mask_image` | 蒙版图，透明区域将重绘 |
| `seed` | 随机种子，0 每次生成新图像 |
| `background` | `auto` / `transparent` / `opaque`；仅支持透明的模型才显示，不支持时会被自动丢弃并记录日志 |
| `num_images` | 生成数量，1-9 下拉选择（默认 1） |

### 批量生成（`num_images`）

⚠️ **上游不支持真正的多图返回**：文档明确写了 `n` 字段发了也只回 1 张，却按 N 张计费。
所以本节点的 N 张**一律是本地并发发 N 个独立请求**，再合并成一个 batch。**不会发送 `n` 字段，不会被多计费**。

这一点**与模型版本无关**，2.0 和 2.5 都支持。

- 并发线程数 = `min(num_images, 9)`，总耗时接近单张耗时，而不是单张 × N
- 返回值尺寸不一致时（例如 `size=auto`），会自动统一缩放到第一张的尺寸再合并
- 部分请求失败时仍会输出成功的部分，并在 `info` 中提示失败数量；全部失败才返回空图
- `info` 中的 Token 使用量是 N 张的**合计值**，并附 `$0.03/张` 的费用估算

> ⚠️ **成本与限流**：生成 N 张 = N 倍计费。并发过高可能触发上游 429 限流，建议首次使用时先用 2-3 张试水。

## 使用示例

### 1. 文生图

最简单的用法，直接输入提示词即可：

```
1:1 方形构图，一只穿着汉服的猫站在故宫红墙前，摄影质感
```

### 2. 切到 2.5 出高质量图

`model` 选 `gpt-image-2.5-sunburst-vip`，`quality` 选 `max`，`size` 选 `2048x2048`。
切换后下拉框会自动只显示该模型支持的选项（2.5 的 quality 会比 2.0 多两档）。

### 3. 图片编辑

连接输入图像，描述想要的变化：

```
把背景从室内换成海边日落，保留人物细节
```

### 4. 多图融合

连接多张输入图像，prompt 中用「图1/图2」指代：

```
把图1的人物放进图2的场景，沿用图3的色彩风格
```

### 5. Mask 局部重绘

上传原图和带透明通道的 MASK：

```
把天空换成粉色晚霞
```

> MASK 要求：与原图相同尺寸，带 alpha 通道，透明区域 = 要重绘的部分
> ⚠️ 反向 `-vip` 通道的 mask **不保证只重绘遮罩区域**（实测整图重生成），需要精确 inpainting 请用官方代理线的 `gpt-image-2`

### 6. 批量生成

把 `num_images` 设为 4，接上 PreviewImage 即可一次预览 4 张：

```
1:1 方形构图，一只穿着汉服的猫站在故宫红墙前，摄影质感
```

输出为 shape `[4, H, W, 3]` 的 batch，可直接接 SaveImage 批量保存。

## 输出节点

| 节点 | 类型 | 说明 |
|------|------|------|
| `IMAGE` | tensor | 生成的图像，`num_images=N` 时为 N 张的 batch |
| `STRING` | text | 生成信息、参数收敛提示和 Token 使用量（批量时为合计） |

## 实现说明：动态下拉是怎么做的

ComfyUI 的 `INPUT_TYPES` 只在节点加载时求值一次，**光靠 Python 做不到"改了 A 下拉就变 B 下拉的选项"**。本插件用了三层，任何一层失效都不会炸：

| 层 | 位置 | 作用 |
|----|------|------|
| 能力表 | `model_config.py` | 唯一数据源：6 个模型 × sizes / qualities / 默认值的注册表 |
| 后端接口 | `GET /gpt-image2/models` | 把注册表发给前端，避免 JS 里再抄一份导致漂移 |
| 前端 JS | `js/gpt_image2.js` | 监听 `model` 变化，动态改 `size` / `quality` 的 `options.values`，并控制 `background` 显隐 |
| 兜底 | `gpt_image2_node.py` | 就算 JS 没生效，Python 侧仍会按模型收敛 `quality` / `size` / `background` 再发出去 |

所以：**Python 端返回的永远是全部选项的并集**，前端负责收窄，服务端负责兜底。

## 注意事项

### 超时设置

- `high` / `max` 画质 + 2K/4K 实测可能需要 **3-5 分钟**
- 节点默认超时 **360 秒**（文档建议 ≥300s）
- 草稿测试建议用 `medium` 或 `low` 画质

### 计费边界

- **HTTP 5xx → 不计费**，可直接重试
- **HTTP 200 但正文是文本软拒绝 → 仍然计费**（协议层看起来像正常返回）
- 鉴权失败、参数校验失败 → 不计费
- `num_images=N` → N 张计费，N 张返回（本地并发，不是上游 `n`）

### 迁移注意

- ❌ **不支持** `input_fidelity`（强制启用 high-fidelity）
- ❌ **`output_format: jpeg` 会被静默忽略**，实际仍返回 PNG
- ❌ 不要手动发 `n` 字段：计费 ×N 但只回 1 张
- ⚠️ `mask` 接受但不保证局部重绘（反向通道）
- ✅ 多图最多 5 张
- ✅ `b64_json` 返回纯 base64（无前缀；代码同时兼容带前缀的情况）

## 错误处理

| 状态码 | 含义 | 建议 |
|--------|------|------|
| 400 | 参数非法 | size 不在 30 种预设里 / quality 档位不被该模型接受 |
| 401 | 令牌无效 | 检查 Bearer Token |
| 403 | 内容审核拦截 | 调整 prompt |
| 429 | 限流 / 上游饱和 / 余额不足 | 指数退避重试；批量生成时降低 `num_images` |
| 500 | 上游计算波动，4K 更常见 | **降到 2K Recommended 重试**，5xx 不计费 |
| 超时 | 高峰偶发 | 等待后重试 |

全部失败时，`info` 会输出逐条失败明细 + 针对性排查建议，不用去翻控制台。
